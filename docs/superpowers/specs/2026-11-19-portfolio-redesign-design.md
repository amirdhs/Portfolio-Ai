# amirdhs.com — Portfolio Redesign (Design)

Date: 2026-11-19 · Status: draft for approval

## Intent

amirdhs.com is Amir Dehestani's **portfolio**. A visitor (a prospective client
or collaborator) should come away with a strong sense of who Amir is and what
he builds, see his work, and get in touch. The current site reads like a
service-agency brochure in champagne gold. The redesign gives it the look and
motion of the reference reel (kabarza "depth" site): dark UI, neon-lime
accents, a glowing 3D perspective grid, images that tilt in depth with
scan-line overlays, glitch transitions between sections, oversized type on
lime slabs — plus a live 3D robot as the hero centrepiece.

## Goals

- Portfolio-first homepage: hero (name + robot) → selected work → what I do →
  about (portrait) → contact.
- Live, interactive 3D robot in the hero (follows the cursor, waves on load,
  reacts to scroll).
- Reference-style effects: grid floor, depth-tilt images/cards with lime
  scan-lines, glitch section transitions, lime "slab" sections with huge type.
- Every existing page restyled through shared tokens and components.

## Non-goals

- No new pages, no URL changes, no CMS, no change to the contact form's
  backend (`/api/inquiry`), SEO metadata, structured data, sitemap or
  `llms.txt` beyond what copy changes require.
- No Blender pipeline (decided: robot built in code).

## Anti-goals (failure even if it "works")

- Lost search visibility: removed pages, changed URLs, headings or text
  hidden from crawlers, LCP pushed out by 3D.
- A site that is unusable with reduced motion, keyboard only, or on a
  mid-range phone (janky scroll, hot battery).
- Looking like a template or a straight clone of the reference — it must read
  as AMIR.

## Constraints

- Next.js 16.4 (App Router, Cache Components, static prerender), React 19.3,
  Tailwind v4, tokens in `src/styles/tokens.css`. Read
  `node_modules/next/dist/docs/` before touching framework APIs.
- DE at `/`, EN at `/en`; all copy lives in `src/content/{de,en}` and
  `src/i18n/dictionaries`.
- Budgets (user rules): landing JS < 150 KB gz for first load; LCP < 2.5 s,
  CLS < 0.1, INP < 200 ms. The 3D bundle is excluded from first load by
  lazy-loading after the hero text paints.
- Motion on compositor-friendly properties only; `prefers-reduced-motion`
  honoured everywhere.
- Existing test suites (Vitest unit, Playwright e2e + axe) must stay green;
  hero e2e tests that assert the old video hero are rewritten for the new hero.

## Approaches considered (robot)

1. **Live 3D in the browser with three.js — chosen.** Interactive, sharp at
   any resolution, easy to tie to cursor/scroll. Costs ~150 KB gz, loaded
   lazily; static fallback for reduced motion / no WebGL.
2. Blender-rendered video loop. Cinematic and light on old phones, but not
   interactive and every change needs a re-render.
3. Model in Blender, export glTF, animate live. Most work; with scripted
   modelling it gives no real gain over building in code.

Amir picked 1.

## Design

### Visual system (replaces champagne-gold tokens)

- Surfaces: near-black with a faint green cast (`oklch(13% 0.01 150)` family).
- Accent: neon lime (`oklch(90% 0.22 125)` area) used as fill (lime slabs,
  primary buttons with near-black text) and as light (grid lines, scan-lines,
  glows). Lime text on dark only where contrast ≥ 4.5:1.
- Typography: keep Schibsted Grotesk (heavy weights, tight tracking for
  display) + IBM Plex Mono for labels/eyebrows. Display sizes increase; lime
  "highlight box" behind one key word in headlines (as in the reference).
- Logo: the gold metallic wordmark gets a white/neutral variant generated by
  `scripts/build-brand-assets.mjs`; the gold file stays in the repo.

### Homepage structure

```
Header: AMIR wordmark · Work · Services · Process · About · Contact · DE/EN
Hero:   name + one-line role, headline with lime highlight word,
        2 CTAs (see work / get in touch) | 3D robot, lime grid floor
Work:   selected projects as depth-tilt cards (lime scan-lines on hover)
Slab:   full-bleed lime section, huge type, "what I do" (services)
Process / Why: condensed, dark
About:  portrait with depth effect + short bio (FounderStrip reworked)
FAQ preview (kept for SEO), then glitch transition into Contact CTA
Footer
```

### The robot

- Stylised, friendly, built from three.js primitives (rounded body, visor
  head with lime glowing eyes, simple arms), matte dark material with lime
  emissive accents; stands on the grid floor.
- Behaviour: idle float/breathing; head and eyes track the pointer; wave on
  first appearance; as the hero scrolls out it turns/leans away. Pauses
  rendering when off-screen or tab hidden.
- Loading: client component, dynamically imported after first paint;
  placeholder is a static PNG render of the same robot (also the reduced-
  motion and no-WebGL fallback). Plain three.js (no react-three-fiber) to keep
  weight down.

### Effects

- **Grid floor:** WebGL in the hero (same canvas as the robot); CSS-only
  perspective grid elsewhere.
- **Depth tilt:** cards and the portrait rotate in 3D toward the pointer
  (CSS transforms), with a lime scan-line/grid overlay that brightens on
  hover. The portrait additionally gets a shader displacement using a
  generated depth map. Touch devices: gentle tilt on scroll instead.
- **Glitch transitions:** sections reveal with a short RGB-split/slice
  effect via `clip-path` + transforms on IntersectionObserver; one-shot, no
  scroll-jacking.
- All effects disabled or reduced to fades under `prefers-reduced-motion`.

### Inner pages

Restyled via tokens and shared components (`Button`, `SectionHeading`,
`PageHeader`, `ProjectCard`, `CtaBand`, header/footer); page headers get the
CSS grid floor; project cards get the depth tilt. No structural changes.

## Decided with Amir

- **Voice:** the hero and homepage section headings/leads are rewritten in
  first person ("I build …"), DE and EN. Inner pages keep their wording.
- **Work section:** keeps the 4 concept projects (still labelled as concepts);
  each card gets code-drawn lime wireframe artwork by category. Real
  screenshots can replace them later without code changes beyond adding an
  image field.

## Left to the builder

- Exact oklch values, spacing, and type scale within the direction above.
- Robot proportions and animation curves.
- How the portrait depth map is produced (hand-built or luminance-based).
- Exact first-person wording (keeping the same facts and claims as today).

## Calls made by Claude (please check)

- Neon lime replaces champagne gold as the accent; logo shown in white.
- Fonts kept (Schibsted Grotesk + IBM Plex Mono) rather than new ones.
- Plain three.js instead of react-three-fiber, to keep the bundle small.
- FAQ preview stays on the homepage because it carries FAQ structured data.
- The old hero video and chat mock-up are removed from the homepage (files
  stay in the repo).
